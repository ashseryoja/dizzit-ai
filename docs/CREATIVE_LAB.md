# Creative Lab

Отдельная лаборатория `/creative-lab`, не часть обычных инструментов проекта.
Шесть стартовых шаблонов: Editorial frames (4 фото), Collected moments (5),
Before / After (2), Fast cuts (6), Бумажный мир (1, ИИ-фото), Into paper (1, ИИ + motion).
Категории: Motion Graphics, ИИ-фото, Тренды видео, ИИ + Motion, Для интерьеров.
Видео без звука; экспорт H.264 MP4, 30 fps, 1080×1920 / 1080×1080 / 1920×1080.
ИИ-фото — PNG с длинной стороной 2048 px. ИИ вызывается только по кнопке пользователя.

## Где хранятся файлы

- `src/creative-lab/catalog.json` — каталог, категории, число слотов, форматы, примеры.
- `src/creative-lab/composition.tsx` — анимации Remotion, общие для предпросмотра и MP4.
- `src/creative-lab/remotion.tsx` — точка входа для рендера.
- `public/creative-lab/demos/` — готовые MP4-примеры и JPEG-обложки. Хранятся в Git.
- `public/creative-lab/examples/` — готовые примеры ИИ-фото. Хранятся в Git.
- `.data/creative-lab/<uuid>/` — входные фото, JSON состояния и `result.mp4` / `result.png`.
  Это обычная папка на диске, исключённая из Git. Postgres и Vercel Blob не используются.
- Браузер: отдельная IndexedDB `dizzit-creative-lab`, только черновики текущих шаблонов.
  Не участвует в синхронизации или сборке мусора основных инструментов сайта.

## Локальный запуск

```sh
npm install
npm run creative:worker
# В другом терминале:
npm run dev
```

Сервис рендера по умолчанию доступен только на `127.0.0.1:4318`.
Next проксирует запросы через `/api/creative-lab/*` с обычной авторизацией сайта и
проверкой Origin. Ключ сервиса не передаётся в браузер.
При первом видеорендере Remotion скачивает Chrome Headless Shell. Нужен доступ в сеть.
Остальные рендеры используют установленный браузер. Шаблоны не загружают внешние ресурсы.

```sh
npm run creative:demos # Пересобрать готовые MP4 и обложки после правки анимаций
npm run check:creative
npm run check:creative:integration # Отдельный временный worker, реальный MP4, без ИИ
npm run type-check
npm run lint
```

Демонстрационные ролики облегчены до 540×960; пользовательский экспорт — 1080p.
Большие наборы фото перед отправкой адаптивно сжимаются до общего JSON <4 МБ,
чтобы не упереться в лимит входящего запроса serverless-платформы.

## Размещение сайта

**Обычная serverless-функция не подходит для постоянного рендера и дискового архива.**
Для опубликованного сайта нужен отдельный работающий Node.js-сервис с постоянным
диском (либо тот же постоянно работающий сервер, где размещён Next).
Просто задеплоить страницу на Vercel недостаточно: каталог откроется, но экспорт
останется недоступен до подключения сервиса. Эта реализация не развёртывает новый сервер.

Настройки окружения Next:

```dotenv
CREATIVE_LAB_WORKER_URL=https://your-private-render-service.example
CREATIVE_LAB_WORKER_TOKEN=<случайный секрет не короче 24 символов>
```

Настройки процесса `npm run creative:worker`:

```dotenv
CREATIVE_LAB_HOST=127.0.0.1
CREATIVE_LAB_PORT=4318
CREATIVE_LAB_DIR=/absolute/path/on/persistent-disk/creative-lab
CREATIVE_LAB_WORKER_TOKEN=<тот же секрет>
```

Скрипт Node не читает `.env.local` автоматически: передайте переменные процессу
через supervisor/контейнер/окружение. На одном хосте URL может быть
`http://127.0.0.1:4318`. Для другого хоста — HTTPS reverse proxy и firewall;
не открывайте незащищённый рендер в Интернет. При bind не на localhost сервис
потребует токен. Сайт должен оставаться закрыт текущей парольной авторизацией.

Реализация для личной лаборатории/одной команды: архив общий для пользователей
одного установленного сайта, **не multi-tenant**. Для публичного сервиса потребуется
отдельная модель владельцев, квоты и авторизация каждого результата.
Запускайте один worker на папку: очередь последовательная, одновременно до пяти
активных заданий. Не используйте несколько процессов с общим диском.
После перезапуска queued продолжаются, interrupted rendering становятся retryable error.
Автоматического удаления результатов нет: папка растёт; настройте резервное
копирование и следите за свободным диском. Входные данные сохраняются для повтора.

## ИИ и стоимость

Бумажные шаблоны используют существующий `requestImage` и `/api/images`, без
`storeKey`: результат не попадает в основное облачное хранилище проекта.
Текст рецепта — `PAPER_PROMPT` в `src/creative-lab/types.ts`.
Без подключённого провайдера кнопка ИИ недоступна; подмены генерации фильтром нет.
Motion-шаблоны не вызывают ИИ. Они используют вычислительные ресурсы сервера;
бесплатный аккаунт чат-сервиса не означает бесплатный API генераций.
ИИ-кадр кэшируется до отправки в очередь: повтор экспорта не вызывает ИИ ещё раз.
При замене фото/формата нужна новая генерация. Пока идёт ИИ-этап, страницу нужно
держать открытой; после получения номера задания сборка продолжается на сервере.

## Как добавить шаблон

1. Добавить запись с уникальным id в `catalog.json`, слоты и локальные demoImages.
2. Реализовать композицию в `composition.tsx`; при новом ИИ-рецепте добавить его
   явный обработчик в `client.ts` (текущие ИИ-шаблоны используют только paper).
3. Запустить `creative:demos`, сохранить готовые MP4/JPEG в проекте.
4. Проверить все форматы, число слотов, экспорт и `check:creative`.

## Происхождение примера «Бумажный мир»

`public/creative-lab/examples/paper.jpg` создан встроенным imagegen (не CLI),
из локального `public/images/invite/restyle-source.jpg`. Остальные демо используют
существующие демонстрационные изображения проекта. Промпт генерации примера:

> Use case: style-transfer. Edit target: supplied interior photo. Create a beautiful
> handcrafted paper-cut diorama version of precisely this room for a Creative Lab
> paper-style template example. Preserve camera, bed on right, pillows, rug,
> climbing wall on left, pendant light and all object positions. Every surface
> becomes layered matte colored cardstock, tiny folded paper edges, visible paper
> fibers, warm ivory and sage colors, soft physical contact shadows. Full bleed
> vertical composition matching original, no border, no text, no watermark.
> Clearly tactile paper construction rather than a photo filter.

PNG был технически преобразован в JPEG для лёгкой загрузки каталога.

## Проверка реализации (19 сентября 2026)

- `check:creative`: все 6 контрактов/форматов, неверное число кадров,
  опасные URL/пути вместо фото, координаты, подпись и наличие всех примеров.
- `check:creative:integration`: отдельная временная папка и worker; токен,
  запрет прямого browser Origin, реальный MP4 16:9 и PNG, частичное скачивание,
  ошибочный byte range, запрет повтора готовой работы, восстановление после рестарта.
- Браузер: фильтрация, поиск/пустая выдача, остановка примеров, загрузка пары JPG,
  живой предпросмотр, экспорт 1:1, восстановление черновика/результата после reload,
  результат в «Мои работы», адаптивная вёрстка при ширине 390 и 1440 px.
- Проверенный пользовательский MP4: H.264, 1080×1080, 30 fps, 8 секунд.
- `type-check`, полный `lint`, production build — успешно.
- Вызов платного ИИ-провайдера в тестах намеренно не выполнялся.
  Генерация демонстрационного бумажного кадра выполнена отдельно встроенным imagegen.
- Публикация и подключение отдельного production worker в эту локальную реализацию
  не входили: для опубликованного сайта выполните раздел «Размещение сайта».
