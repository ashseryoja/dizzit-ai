# Dizzit AI — правила для работы в этом репозитории

## Общий UI — один компонент на повторяющуюся часть

Экраны инструментов (`src/app/(main)/*/page.tsx`) **не содержат собственной
разметки** композера, панели настроек, панели-галереи пачки, сцены, пакетного
грида, дропзоны, приёма файлов и плавающих слоёв. Всё это — общие компоненты и
хуки: `src/components/tool/tool-shell.tsx`, `tool-composer.tsx`, `render-tray.tsx`,
`stage.tsx`, `tool-dropzone.tsx`, `src/lib/use-attachments.ts`,
`src/lib/use-batch-selection.ts`, `src/lib/tool-jobs.ts`. Страница — это
конфигурация (тексты `LABELS`, опции) плюс логика самого инструмента.

Карта «хочу поменять X на всех экранах → файл Y», описание компонентов,
каталог и каркас новой страницы — **`docs/TOOL_UI.md`**. Читать его перед
любой правкой UI инструментов и перед добавлением нового инструмента.

При любой новой функции или изменении UI:

1. Не копировать разметку из соседней страницы. Отличие одного инструмента —
   проп общего компонента (или слот `extras`/`dock`/`overlay`), а не копия.
2. Новый повторяющийся кусок — новый файл в `src/components/tool/` или хук в
   `src/lib/`, и сразу строка в `docs/TOOL_UI.md` (карта и каталог). Новый
   экспорт без записи в документе не проходит проверку.
3. Тексты — в `LABELS` страницы или пропсами; общие для всех — внутри компонента.
   Внешний вид — рецепты в `src/styles/ds/surfaces.css`, не inline-стили на странице.
4. Перед завершением: `npm run check:ui` (входит в `npm run lint`) и
   `npm run type-check`. Хук в `.claude/settings.json` запускает `check:ui` после
   каждой правки UI-файла — его сообщения нужно исправить, а не обойти.

## Проверка в браузере

Не запускать `npm run build` при живом dev-сервере. Для превью — конфигурации
`dizzit-ai-auto` / `dizzit-ai-solo` из `.claude/launch.json` (отдельные каталоги
сборки); если такие серверы уже подняты другой сессией — открывать их порт, а не
поднимать свой. Картинки в инструменты удобно класть синтетическим `paste`
на `window`.
