# Dizzit AI

Сервис инструментов ИИ для дизайна. Направление: улучшение качества рендеров,
скетч в рендер, генерация материалов и смежные задачи визуализации.

> **Статус: каркас + пять инструментов, картинки считает gpt-image-2.** Сервис
> сменил профиль — раньше здесь считались сметы строительства и ремонта; все
> сметные инструменты удалены. «Редактор рендера», «Ракурсы и детали»,
> «Перенос стиля» и «Генерация материала» генерируют через LaoZhang
> (модель `gpt-image-2`, ~$0.03 за картинку, ключ `LAOZHANG_API_KEY` в
> `.env.local` — см. «Генерация картинок»); без ключа те же инструменты
> работают на локальных canvas-предпросмотрах. «Фото → 3D» ждёт своего
> провайдера (Meshy).

## Экраны

| Маршрут | Что там |
| --- | --- |
| `/` | Редирект на `/enhance` — первый инструмент и есть главный экран |
| `/enhance` | **Редактор рендера**: зона загрузки → галерея обработок + композер внизу |
| `/views` | **Ракурсы и детали**: из одного общего рендера — раскадровка для публикации |
| `/restyle` | **Перенос стиля**: тот же интерьер в другом стиле, геометрия на месте |
| `/photo-3d` | **Фото → 3D**: каркасная 3D-модель предмета по одному фото, сцена крупно |
| `/materials` | **Генерация материала**: тот же UI, текстуры по описанию |
| `/settings` | Профиль, внешний вид (тема), резервная копия данных |

Слева — сайдбар: селектор проектов (создать, переименовать, удалить, поиск),
секция «инструменты» и меню аккаунта внизу. На узких экранах сайдбар
уезжает в шторку, аккаунт — в нижнюю шторку.

**Проект — центральная сущность.** Инструменты крепят свои данные к проекту
по id: обработки рендеров фильтруются по активному проекту, удаление проекта
уносит и их. Стор — `src/stores/project-store.ts`, localStorage-ключ
`dizzit-projects`. Данные прежних сметных ключей (`smeta-chats` и пр.) не
читаются; ключ `smeta-company` жив — в нём название и контакты исполнителя.

## Редактор рендера

Пользователь прикладывает рендер или пачку до 10 файлов (PNG/JPG/WEBP до
32 МБ — кнопкой, переносом файлов или вставкой из буфера) и получает более
реалистичные и детальные версии. **Содержимое кадра не меняется** — геометрия,
материалы и композиция остаются; размер результата — до 1536 px по длинной
стороне (потолок gpt-image-2) в ближайшей из трёх пропорций модели. Это
обещание продукта, поэтому настроек масштаба и «силы» у обработки нет вовсе.

Раскладка повторяет нейрофотосессию UpSound AI: галерея-масонри результатов,
внизу плавающий композер — комментарий к обработке, главная кнопка «Улучшить»
и шестерёнка. Панель настроек раскрывается над композером той же ширины и
содержит всё остальное: пачку рендеров (сетка превью с индикатором качества
исходников по худшему файлу) и выбор контекста сцены (авто / интерьер /
экстерьер / предметный). Карточка живёт статусами «обрабатывается →
готово/ошибка»; по ховеру — «до/после» (удерживать), скачать, удалить; при
ошибке — «Повторить». На пустом экране есть «Показать пример галереи» —
генерирует десяток тестовых рендеров разных форматов (`lib/demo-renders.ts`)
и прогоняет их обычным конвейером.

**Движок** (`src/lib/enhance-engine.ts`): `enhanceRender` собирает промпт из
контекста, заселения, пакетных функций и комментария, прикладывает уменьшенный
исходник (и карту областей точечной правки вторым референсом) и зовёт
gpt-image-2 через `lib/image-generation.ts` (см. «Генерация картинок»).
Результат — до 1536 px по длинной стороне в ближайшей из трёх пропорций
модели. Без ключа провайдера работает `enhanceLocally` — canvas-предпросмотр
(деликатная цветокоррекция в размере исходника), карточка подписана
«предпросмотр без ключа»: нажатие «Улучшить» не может остаться без результата
— принцип ещё сметного профиля. Пачка обрабатывается последовательно:
карточки появляются сразу, статусы догоняют.

**Хранение разделено на два слоя.** Метаданные обработок — zustand+persist
(localStorage, ключ `dizzit-enhancements`), они попадают в резервную копию из
настроек. Изображения (исходник, результат, миниатюры) — IndexedDB
(`src/lib/blob-store.ts`): в localStorage картинкам не место из-за квоты
~5 МБ. Резервная копия JSON изображения НЕ включает — скачивайте результаты
кнопкой на карточке. Осиротевшие блобы подчищает `lib/blob-gc.ts` на входе в
любой инструмент; живыми он считает записи всех инструментов сразу — база
блобов у них общая.

**Заселить сцену** — тумблер в настройках композера (и в обычных, и в
пакетных). Единственная функция, которая ДОБАВЛЯЕТ в кадр новое: людей и
растения по контексту сцены и в её масштабе — интерьеру люди и растение в
кадке, экстерьеру прохожие и дерево, предметной съёмке только веточка в углу.
Модели это уходит строкой промпта; локальный предпросмотр рисует стаффаж —
плоские силуэты, как на эскизах архитекторов (`src/lib/scene-population.ts`,
детерминированно по id записи). В подписи карточки — «заселение».

## Ракурсы и детали

Из одного общего рендера — раскадровка для публикации, как в карусели
дизайнера: детали крупно, фактуры, фрагменты и виды с других точек, без
3D-модели. Тот же UI, что у редактора рендера: галерея-масонри сетов,
композер с комментарием («что показать крупно») и кнопкой «Построить» и один
выбор в его настройках:

| Набор | Кадры |
| --- | --- |
| **Сет** | сверху, снизу, две детали, фактура, фрагмент — готовая карусель |
| Детали | четыре крупных плана предметов |
| Ракурсы | сверху, снизу, слева, справа |
| Фрагменты | четыре зоны помещения |

Ракурсы — вся сцена в пропорции исходника; крупные планы — портрет 4:5
(`ShotKind` в `types`, наборы — `PRESET_SHOTS` в `lib/view-engine.ts`).

Пока пачка приложена, экран живёт **как редактор рендера**: справа
панель-галерея с миниатюрами (`RenderTray`, на узких экранах — `RenderStrip`
под сценой), в центре — выбранный рендер во весь экран (стрелки, счётчик),
под ним подпись — какие кадры даст выбранный набор. Сет строится по рабочему
набору: рендер на сцене либо отмеченные в режиме «Выбрать» панели;
«Построить все» показывает набор гридом вместо сцены. Каждый рендер даёт свой
сет; отправленные уходят из панели, остальная пачка остаётся — по ней можно
построить другой набор кадров.

Карточка сета (`components/tool/view-set-card.tsx`) — контактный лист: плитки
по два в ряд, соседи в ряду одной пропорции (сеты так и собраны). Кадры
считаются по три разом (`mapWithConcurrency`), и плитки догоняют по мере
готовности (поле `ready` записи — ключи готовых кадров). У каждой плитки своё скачивание, у сета —
«скачать все», общий план по удержанию и удаление. Блобы кадров лежат в
общем хранилище под ключами `${id}:view-${frame.key}` и
`${id}:thumb-view-${frame.key}` — сборка мусора видит их по префиксу id,
каскадное удаление знает список кадров записи. Метаданные — ключ
`dizzit-views` (`src/stores/views-store.ts`).

Движок (`src/lib/view-engine.ts`): `prepareViewSet` один раз уменьшает общий
план до референса, и каждый кадр — свой запрос к gpt-image-2 со своим
промптом (`buildViewPrompt`): ракурсы — та же сцена с другой точки в
пропорции исходника, крупные планы — портрет, обрезанный до 4:5. Комментарий
«что показать крупно: ваза, кресло» раздаётся крупным планам по порядку; без
него у каждого кадра типовой сюжет по номеру, чтобы детали не повторялись.
Без ключа — предпросмотр: крупные планы вырезаются по карте градиентов
(окно с максимумом «насыщенности», приоритет средне-нижней части кадра, штраф
рядом с уже выбранными окнами — план сета считается один раз), ракурсы —
перспективное искажение кадра (полосы-трапеция и вписанный прямоугольник).

Пустой экран — карусель из одного рендера: слева общий план (эскиз комнаты
`components/tool/room-sketch.tsx`, общий с переносом стиля), справа четыре
кадра из него — вырезки того же эскиза через `viewBox`; по общему плану
ходит рамка «откуда вырезано», подсветка плиток идёт синхронно (`.vo-*` в
`surfaces.css`).

## Перенос стиля

Готовый интерьер (рендер или фото) переводится в другой стиль. Каталог —
двенадцать популярных направлений (`STYLES` в `src/lib/restyle-engine.ts`:
скандинавский, неоклассика, джапанди, лофт, минимализм, мид-сенчури, бохо,
ар-деко, средиземноморский, прованс, ваби-саби, контемпорари) плюс «Свой
стиль» по описанию (слова-подсказки у каждого стиля: «добавить элементы
джапанди» → джапанди). Геометрия помещения остаётся, меняются отделка, цвета
и дизайн мебели — это обещание продукта, поэтому результат всегда в размере
исходника.

Пока пачка приложена, экран живёт **как редактор рендера**: справа та же
панель-галерея с миниатюрами (`RenderTray`, на узких экранах — `RenderStrip`
под сценой), левее неё такая же высокая **панель стилей** со своим скроллом
(на xl закреплена, ниже — блок под сценой), в центре — выбранный интерьер
(стрелки, счётчик). Строка стиля (`components/tool/style-picker.tsx`) —
название, справа четыре самых узнаваемых материала и счётчик остальных («+11»),
под названием характеристика. У каждого стиля 12–16 материалов — стены, пол,
конструкции, мебель, текстиль, свет, декор — по тому, из чего стиль собирают
на практике: у лофта кирпич красный и белёный, бетон, наливной пол, состаренная
доска, трубы, балки, сетка, кортен, кожа, чёрный металл, лампы Эдисона, стекло
в чёрных рамах, канат. Образцы — SVG-фактуры (`components/tool/material-swatch.tsx`,
около пятидесяти рисунков: кирпич, бетон, доски, ёлочка, шеврон, мрамор, сланец,
булыжник, терраццо, плитка, мозаика, глазурь, лён, джут, бархат, шёлк, букле,
овчина, кожа, ротанг, канат, макраме, виши, кружево, обои, ковёр, металл,
чугун, трубы, сетка, ржавчина, стекло, зеркало, лак, лампа Эдисона, неон,
бамбук, бумага, сёдзи, татами, пробка, мох…). Первым в списке —
«Свой стиль». Клик по строке выбирает стиль, он же — сегмент в панели
композера; плейсхолдер строки ввода меняется на «Уточнения к стилю…» — туда
пишут «без кирпича», «светлее пол». «Свой стиль» без описания — не задание:
композер показывает замечание и подсвечивает, что выбрать (та же механика
`notice`/`attentionKey`, что у редактора рендера).

Выбранный стиль открывает **секцию над композером** той же ширины
(`components/tool/style-dock.tsx`, слот `dock` композера): название,
характеристика и все материалы стиля крупно, у каждого галочка. Все включены;
снятая галочка исключает материал из рендера — «лофт, но без кирпича»;
«вернуть все» возвращает галочки.
Снятые материалы уходят в запись полем `excluded` и видны в подписи карточки
(«без: кирпич»); крестик сбрасывает стиль на «свой». При наведении на строку
списка (и фокусе с клавиатуры) под ней или над ней появляется **превью
стиля** — окошко с интерьером в этом стиле: фото из каталога (`photo` в
`STYLES`, путь из `/public`), а пока фото нет — нарисованная сцена
(`style-scenes.tsx`, по одной на все двенадцать стилей). Стоковые фото в
продукт не вшиваем из-за лицензий — сюда кладут собственные.

Стиль применяется к **рабочему набору**, как обработка в редакторе рендера:
интерьер на сцене, либо отмеченные в режиме «Выбрать» панели; «Перенести
все» показывает набор гридом вместо сцены. Обработанные уходят из панели,
остальная пачка остаётся — к ней можно применить другой стиль. Метаданные —
ключ `dizzit-restyles` (`src/stores/restyle-store.ts`), карточка — общая
`ToolCard` с «до/после».

Движок (`src/lib/restyle-engine.ts`): `restyleRender` собирает промпт из
каталога стиля (`STYLES`: характер и материалы за вычетом снятых галочкой) и
комментария; «свой стиль» без узнаваемых слов уходит модели самим описанием,
без подмены семейством. Исходник — референс, gpt-image-2 меняет отделку, цвета
и мебель, оставляя геометрию. Без ключа — предпросмотр: тональная палитра
стиля canvas-фильтрами, тонировка и виньетка.

Пустой экран — одна и та же комната, в которой по кругу меняется интерьер:
скандинавский → неоклассика → джапанди → лофт. Четыре сцены с общей
геометрией (стены, окно, пол, место дивана) и своей отделкой, мебелью,
светом и декором — `components/tool/style-scenes.tsx`. Смена идёт проходом
малярного валика: входящий слой открывается наклонной clip-path, по кромке
едет светящаяся линия со шлейфом (`components/tool/style-swap.tsx`, `.ss-*`
в `surfaces.css`); подпись стиля и полоска стилей под кадром переключаются
вместе с валиком. В скрытой вкладке цикл стоит, при reduced-motion — статика.

## Генерация материала

Второй инструмент — **тот же UI, что у улучшения рендера**: галерея-масонри,
композер с описанием и кнопкой «Сгенерировать», панель той же ширины с
референсами и выбором семейства (авто / дерево / камень / металл / ткань).
Референсы не обязательны: материал генерируется по чистому описанию, референс
задаёт базовый тон, «авто» выводит семейство из текста («дуб» → дерево).
Результат — квадратный тайл 1024×1024. Метаданные — ключ `dizzit-materials`
(`src/stores/material-store.ts`).

Движок (`src/lib/material-engine.ts`): `generateMaterial` просит у gpt-image-2
бесшовную текстуру по описанию и семейству (`buildMaterialPrompt`), референс
уходит картинкой — модель берёт его тон и характер. Без ключа —
`generateMaterialLocally`: процедурные canvas-текстуры, детерминированные по
id записи («Повторить» рисует то же).

**Паттерн инструмента переиспользуемый**: карточка галереи и композер живут в
`src/components/tool/` и параметризуются текстами и набором опций — третий
инструмент (скетч→рендер) собирается из тех же деталей.

## Что удалено при смене профиля

Экраны `/chat`, `/manual`, `/estimate`, `/price-book`; компоненты чата и
таблиц сметы; движок расчёта, справочник цен, экспорт, приём вложений;
LLM-адаптер и `api/estimate`; сторы смет и справочника; типы сметы.

Если что-то из этого понадобится как референс (например, приём вложений
пригодится инструментам с загрузкой картинок) — смотреть историю копий
проекта: репозиторий без git, файлы удалены физически.

## Дизайн-система

**Тёмно-серый фон, чистый белый акцент, плоские поверхности.**

Градиентов нет нигде: ни фонов, ни кнопок, ни рамок, ни бликов. Глубину даёт
разница светлот трёх слоёв и одна рамка в 1px.

```
--bg-page    #1e1e21   фон приложения
--bg-surface #26262a   панели, сайдбар
--bg-raised  #2e2e33   карточки и поля внутри панели
--accent     #ffffff   плотная белая заливка
--line       rgba(255,255,255,0.09)
```

Иерархию текста держит лестница прозрачностей `--fg-1 … --fg-6`. Цвет в системе
один — `--danger`, для удаления.

**Плотная белая заливка зарезервирована за акцентными местами** (главная
кнопка, активный пункт меню). Больше нигде — иначе акцент перестаёт читаться.

Шрифты: `Unbounded` (заголовки), `Garet-Book` (текст). Отдаются с
`Cache-Control: immutable` — **при замене содержимого файла обязательно менять
имя** (`-v3` и т.д.), иначе браузер отдаст старую версию из кэша.

### Правило про анимации

Видимость навигации не зависит от анимаций. Клок CSS/JS-анимаций замирает в
скрытой вкладке: кадр с `opacity: 0` в такой момент прячет меню целиком
(проверено). Поэтому вход меню — **только сдвиг**, без прозрачности, без
`fill-mode` и без ступенчатых задержек, а мобильная шторка ездит `transition`,
а не анимацией с подменой стилей.

Заставка входа (`intro-splash.tsx` + `scripts/build-intro-morph.mjs`) — часть
бренда, не инструментов: рукописный «Dizzit AI» морфится в логотип. Осталась.

## Генерация картинок: LaoZhang gpt-image-2

Все картиночные инструменты считает одна модель через один вход. Перенос из
UpSound (`services/cover_generator/image_generator.py`,
`_generate_via_laozhang_images_api`): OpenAI-совместимый Images API LaoZhang.

```
движок инструмента (промпт + референсы)        src/lib/{enhance,restyle,view,material}-engine.ts
  └─ requestImage()                            src/lib/image-generation.ts   ← клиент, ключа нет
       └─ POST /api/images (multipart)         src/app/api/images/route.ts   ← тонкий прокси
            └─ generateImage()                 src/server/laozhang.ts        ← ключ, «server-only»
                 ├─ /v1/images/generations     текст → картинка (JSON)
                 └─ /v1/images/edits           референсы + текст (multipart, image / image[])
```

- **Ключ** — `LAOZHANG_API_KEY` в `.env.local` (шаблон — `.env.example`), на
  Vercel — Environment Variables. В браузер не попадает: `src/server/*`
  импортирует `server-only`, клиентский импорт ломает сборку.
- **Модель** — `gpt-image-2` (`LAOZHANG_IMAGE_MODEL`), ~$0.03 за картинку.
  Принимает `size` из трёх значений — 1024×1024, 1536×1024, 1024×1536 — и не
  принимает `quality`/`output_format`; `sizeForAspect` выбирает ближайшую
  пропорцию к исходнику. Ответ — `data[0].b64_json` или `data[0].url`.
- **Референсы** перед отправкой уменьшаются до 1536 px по длинной стороне
  (`prepareReference`): модель больше не использует, а 30-мегабайтный рендер
  уезжает мегабайтом — в лимит тела запроса на Vercel.
- **Без ключа** `/api/images` отвечает 503 `provider_not_configured`, и
  `withImageProvider` переключает движок на canvas-предпросмотр; запись
  получает `engine: "preview"`, карточка — подпись «предпросмотр без ключа».
  Ошибка модели предпросмотром **не** подменяется: карточка показывает причину
  и «Повторить».
- **Ошибки** провайдера классифицируются на сервере (ключ, пустой баланс
  аккаунта LaoZhang, политика контента, лимит, таймаут, сеть) и уходят на карточку понятным текстом без сырого тела
  ответа; временные (429/5xx/сеть) один раз повторяются.
- **Локальная проверка без расходов** — `npm run fake:images` поднимает
  фальшивый LaoZhang на `:4321`; конфигурация `dizzit-ai-fake-images` в
  `.claude/launch.json` запускает dev-сервер, направленный на него.

Очереди, воркера, квот и учёта расходов пока нет — запрос к провайдеру
держится открытым до ответа (`maxDuration = 300` у роута). Куда это растёт —
[`docs/PLATFORM_ARCHITECTURE.md`](docs/PLATFORM_ARCHITECTURE.md).

## Куда добавлять новый инструмент

Экран инструмента **не пишется с нуля и не копируется с соседнего**: композер,
панель настроек, панель-галерея пачки, сцена, дропзона и приём файлов — общие
компоненты и хуки, страница лишь задаёт тексты, опции и движок. Что из чего
собрано, где что править, чтобы изменилось на всех экранах, и каркас новой
страницы — в [`docs/TOOL_UI.md`](docs/TOOL_UI.md).

1. Экран — `src/app/(main)/<tool>/page.tsx` по каркасу из `docs/TOOL_UI.md`.
2. Пункт меню — секция «инструменты» в `src/components/app-sidebar.tsx`
   (комментарий отмечает место; паттерн пунктов сохранён в `navItemClass`).
3. Данные инструмента — свой стор в `src/stores/`, привязка к проекту по
   `projectId` из `useProjectStore`.
4. Картинки — через общий вход `src/lib/image-generation.ts` (`requestImage`
   + `withImageProvider` для предпросмотра без ключа), промпт — в движке
   инструмента. Другой провайдер или другая механика (3D, видео) — свой
   `src/server/<provider>.ts` с `import "server-only"` и роут
   `src/app/api/<tool>/route.ts`; ключи только в серверном окружении
   (`.env.local`), в браузер не отдавать.

Генерация и обработка изображений — долгие операции: им нужны очередь,
объектное хранилище и живой прогресс, а не HTTP-запрос на минуту. Механика —
в [`docs/UPSOUND_ARCHITECTURE.md`](docs/UPSOUND_ARCHITECTURE.md) (очереди,
admission control, хранилище файлов, AI-провайдеры, SSE-прогресс) — документ
писался для сметного профиля, но описывает общую инфраструктуру и остаётся
планом подключения.

## Что осознанно НЕ сделано

- **Нет авторизации и квот.** Данные локальные, пользователь один;
  `/api/images` принимает запросы без проверки, каждая генерация — ~$0.03 без
  потолка расходов. Первое, что нужно перед публичным доступом
  (`PLATFORM_ARCHITECTURE.md`, §5–6).
- **Файлы хранятся в браузере.** Исходники и результаты живут в IndexedDB
  этого браузера; в резервную копию JSON они не входят. На генерацию
  провайдеру уходит уменьшенная копия исходника.
- **Нет очереди и воркера.** Запрос к провайдеру держится открытым до ответа;
  закрытая вкладка — «Повторить» на карточке.
- **«Фото → 3D» пока локальный.** Каркас из библиотеки вместо настоящей
  модели — до подключения Meshy.
- **Нет отмены удаления.** Удаление проекта или обработки необратимо, поэтому
  спрашивает подтверждение.
