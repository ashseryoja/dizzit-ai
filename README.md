# Dizzit AI

Сервис инструментов ИИ для дизайна. Направление: улучшение качества рендеров,
скетч в рендер, генерация материалов и смежные задачи визуализации.

> **Статус: каркас + два инструмента.** Сервис сменил профиль — раньше здесь
> считались сметы строительства и ремонта; все сметные инструменты удалены.
> «Редактор рендера» и «Генерация материала» работают end-to-end на
> локальных движках-предпросмотрах; серверные AI-провайдеры подключаются
> отдельно (см. «Куда добавлять новый инструмент»).

## Запуск

```bash
npm install
npm run dev
```

`http://localhost:3010`

```bash
npm run build       # продакшн-сборка
npm run start       # продакшн-сервер
npm run type-check  # TypeScript
npm run lint        # ESLint
```

> Не запускать `npm run build` при живом `npm run dev`: они делят каталог
> `.next`, и dev-сервер после этого отдаёт 500. Сначала остановить dev.

## Экраны

| Маршрут | Что там |
| --- | --- |
| `/` | Редирект на `/enhance` — первый инструмент и есть главный экран |
| `/enhance` | **Редактор рендера**: зона загрузки → галерея обработок + композер внизу |
| `/photo-3d` | **Фото → 3D**: каркасная 3D-модель предмета по одному фото, сцена крупно |
| `/materials` | **Генерация материала**: тот же UI, текстуры по описанию |
| `/settings` | Профиль, внешний вид (тема), резервная копия данных |

Слева — сайдбар: селектор проектов (создать, переименовать, удалить, поиск),
секция «инструменты» и меню аккаунта внизу. На узких экранах сайдбар
уезжает в шторку, аккаунт — в нижнюю шторку.

**Проект — центральная сущность.** Инструменты крепят свои данные к проекту
по id: обработки рендеров фильтруются по активному проекту, удаление проекта
уносит и их. Стор — `src/stores/project-store.ts`, localStorage-ключ
`dizzit-projects`. Данные прежних сметных ключей (`smeta-chats` и пр.) не
читаются; ключ `smeta-company` жив — в нём название и контакты исполнителя.

## Редактор рендера

Пользователь прикладывает рендер или пачку до 10 файлов (PNG/JPG/WEBP до
32 МБ — кнопкой, переносом файлов или вставкой из буфера) и получает более
реалистичные и детальные версии. **Содержимое кадра не меняется** — геометрия,
материалы, композиция и РАЗМЕР остаются: результат всегда в разрешении
исходника. Это обещание продукта, поэтому настроек масштаба и «силы» у
обработки нет вовсе.

Раскладка повторяет нейрофотосессию UpSound AI: галерея-масонри результатов,
внизу плавающий композер — комментарий к обработке, главная кнопка «Улучшить»
и шестерёнка. Панель настроек раскрывается над композером той же ширины и
содержит всё остальное: пачку рендеров (сетка превью с индикатором качества
исходников по худшему файлу) и выбор контекста сцены (авто / интерьер /
экстерьер / предметный). Карточка живёт статусами «обрабатывается →
готово/ошибка»; по ховеру — «до/после» (удерживать), скачать, удалить; при
ошибке — «Повторить». На пустом экране есть «Показать пример галереи» —
генерирует десяток тестовых рендеров разных форматов (`lib/demo-renders.ts`)
и прогоняет их обычным конвейером.

**Движок сейчас локальный, и это предпросмотр** (`src/lib/enhance-engine.ts`):
деликатная цветокоррекция canvas-фильтрами, размер не трогается. Настоящее
улучшение — серверная image-to-image модель с очередью и хранилищем; когда
она подключится, локальный движок останется страховкой (нажатие «Улучшить»
не может остаться без результата — принцип ещё сметного профиля). Пачка
обрабатывается последовательно: карточки появляются сразу, статусы догоняют.

**Хранение разделено на два слоя.** Метаданные обработок — zustand+persist
(localStorage, ключ `dizzit-enhancements`), они попадают в резервную копию из
настроек. Изображения (исходник, результат, миниатюры) — IndexedDB
(`src/lib/blob-store.ts`): в localStorage картинкам не место из-за квоты
~5 МБ. Резервная копия JSON изображения НЕ включает — скачивайте результаты
кнопкой на карточке. Осиротевшие блобы подчищает `lib/blob-gc.ts` на входе в
любой инструмент; живыми он считает записи всех инструментов сразу — база
блобов у них общая.

## Генерация материала

Второй инструмент — **тот же UI, что у улучшения рендера**: галерея-масонри,
композер с описанием и кнопкой «Сгенерировать», панель той же ширины с
референсами и выбором семейства (авто / дерево / камень / металл / ткань).
Референсы не обязательны: материал генерируется по чистому описанию, референс
задаёт базовый тон, «авто» выводит семейство из текста («дуб» → дерево).
Результат — квадратный тайл 1024×1024. Метаданные — ключ `dizzit-materials`
(`src/stores/material-store.ts`).

Движок (`src/lib/material-engine.ts`) — процедурные canvas-текстуры,
детерминированные по id записи («Повторить» рисует то же). Это такой же
предпросмотр-заглушка, как у улучшения: серверная модель подключается по
общей схеме.

**Паттерн инструмента переиспользуемый**: карточка галереи и композер живут в
`src/components/tool/` и параметризуются текстами и набором опций — третий
инструмент (скетч→рендер) собирается из тех же деталей.

## Что удалено при смене профиля

Экраны `/chat`, `/manual`, `/estimate`, `/price-book`; компоненты чата и
таблиц сметы; движок расчёта, справочник цен, экспорт, приём вложений;

Если что-то из этого понадобится как референс (например, приём вложений
пригодится инструментам с загрузкой картинок) — смотреть историю копий
проекта: репозиторий без git, файлы удалены физически.

## Дизайн-система

**Тёмно-серый фон, чистый белый акцент, плоские поверхности.**

Градиентов нет нигде: ни фонов, ни кнопок, ни рамок, ни бликов. Глубину даёт
разница светлот трёх слоёв и одна рамка в 1px.

```
--bg-page    #1e1e21   фон приложения
--bg-surface #26262a   панели, сайдбар
--bg-raised  #2e2e33   карточки и поля внутри панели
--accent     #ffffff   плотная белая заливка
--line       rgba(255,255,255,0.09)
```

Иерархию текста держит лестница прозрачностей `--fg-1 … --fg-6`. Цвет в системе
один — `--danger`, для удаления.

**Плотная белая заливка зарезервирована за акцентными местами** (главная
кнопка, активный пункт меню). Больше нигде — иначе акцент перестаёт читаться.

Шрифты: `Unbounded` (заголовки), `Garet-Book` (текст). Отдаются с
`Cache-Control: immutable` — **при замене содержимого файла обязательно менять
имя** (`-v3` и т.д.), иначе браузер отдаст старую версию из кэша.

### Правило про анимации

Видимость навигации не зависит от анимаций. Клок CSS/JS-анимаций замирает в
скрытой вкладке: кадр с `opacity: 0` в такой момент прячет меню целиком
(проверено). Поэтому вход меню — **только сдвиг**, без прозрачности, без
`fill-mode` и без ступенчатых задержек, а мобильная шторка ездит `transition`,
а не анимацией с подменой стилей.

Заставка входа (`intro-splash.tsx` + `scripts/build-intro-morph.mjs`) — часть
бренда, не инструментов: рукописный «Dizzit AI» морфится в логотип. Осталась.

## Куда добавлять новый инструмент

1. Экран — `src/app/(main)/<tool>/page.tsx`.
2. Пункт меню — секция «инструменты» в `src/components/app-sidebar.tsx`
   (комментарий отмечает место; паттерн пунктов сохранён в `navItemClass`).
3. Данные инструмента — свой стор в `src/stores/`, привязка к проекту по
   `projectId` из `useProjectStore`.
4. Серверная часть — `src/app/api/<tool>/route.ts`; ключи провайдеров только
   в серверном окружении (`.env.local`), в браузер не отдавать.

Генерация и обработка изображений — долгие операции: им нужны очередь,
объектное хранилище и живой прогресс, а не HTTP-запрос на минуту. Механика —
в [`docs/UPSOUND_ARCHITECTURE.md`](docs/UPSOUND_ARCHITECTURE.md) (очереди,
admission control, хранилище файлов, AI-провайдеры, SSE-прогресс) — документ
писался для сметного профиля, но описывает общую инфраструктуру и остаётся
планом подключения.

## Что осознанно НЕ сделано

- **Нет авторизации.** Данные локальные, пользователь один.
- **Файлы не покидают браузер.** Исходники и результаты живут в IndexedDB
  этого браузера; в резервную копию JSON они не входят.
- **Улучшение пока локальное.** Canvas-предпросмотр вместо серверной модели;
  провайдер подключается по схеме из архитектурного дока.
- **Нет отмены удаления.** Удаление проекта или обработки необратимо, поэтому
  спрашивает подтверждение.
